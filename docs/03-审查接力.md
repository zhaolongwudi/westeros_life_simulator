7. ⚠️ **推送（2026-10-07 由 S8-1 实测订正；原规则在本机不适用）**：原写「先 `git pull --rebase origin main`」——**本机没有 git 二进制，跑不了**；且本机与远端可能是**分叉**而非落后（S8-1 当时：本地 `02eb0991` 与远端 `0e4be1e2` 同为 `c6edecbd` 的子提交），rebase 语义也不对。现状与做法：
   - **本机 `github.com` git 协议硬阻塞**（S8-1 时连续 4 次 fetch 全超时），**仅 `api.github.com` 可达**（约 4s）。故 `wg fetch` / `wg pull` 用不了，`wg push` 会自动走 GitHub API 兜底（git 在 `/data/user/0/com.dshphone/files/tools/gitjs/wg.js`，isomorphic-git）。
   - 🔴 **本机 ref 与远端分叉时不要用 `wg push`**：其 API 兜底从本地 HEAD 沿 parent 回溯到远端 HEAD，分叉时**走不到**，会一路回溯到根提交、把整条历史重建成一串新 commit。
   - ✅ **可用做法**：以**远端 HEAD 为 parent**，用 Git Data API 直接建单条 commit（blobs → trees → commits → PATCH ref），内容取**当前工作区**，再把 `refs/heads/main` 与 `refs/remotes/origin/main` 改写对齐。**先备份 ref**，并**排除 `README.md`**（CI 会自动提交 `docs(readme): auto-update changelog [skip ci]`，本地那份永远落后一条，带上会回退 CI 的改动）。
   - **建树建议自检**：用扁平路径重建远端 tree 并与真实 tree sha 比对（S8-1 实测 `a54bad4c` 逐字节一致），确认建树忠实再写。
   - 📌 **工作区出现大量 M/A 不一定是未推送工作**：ref 陈旧时已推送的内容也会显示为本地改动（S8-1 时 13 个 M/A 里只有 4 个是真改动，`batch12_s52*` 与远端逐字节相同）。判断要**逐文件算 blob sha 与远端 tree 比对**，不要看 `status`。
   - 🔴 **2026-10-08（S9-1）新增 4 个坑**（`wg.js` 这次直接不可用，全部手写 API 脚本）：
     1. **`wg.js` 也会挂**：本机 `.git/objects` 只有 153 个松散对象，`wg status/commit/push` 报 `Could not find <sha>` ⇒ **isomorphic-git 读不了本地仓库**，只能走 Git Data API。
     2. **`GET /git/commits/{sha}` 返回 `.tree`**，而 `GET /repos/{o}/{r}/commits/{sha}` 返回 `.commit.tree` —— 写错会 404（`tree.sha [object Object] is not a valid tree`）。BASE 指向 `/git` 时用前者。
     3. **`POST /git/blobs` 会间歇性 500（空 body）**：重试 3~4 次即恢复；不要据此判定脚本错。
     4. 🔴 **建树时根目录的前缀不能写成 `dirPath + '/'`**：根时 `dirPath` 为 `''` ⇒ 前缀变成 `'/'` ⇒ 一个都匹配不上 ⇒ **生成与远端完全相同的空 tree，仍能"通过"完整性检查并推出一条空 commit**。S9-1 实测踩中并已回滚（`61417827`）。**前缀用 `dirPath ? dirPath + '/' : ''`，且必须硬断言 `newTree !== rootTree` 才允许 PATCH ref。**
8. **取证纪律**（本项目最重要的经验）：每次断言先grep/find 核实再写。S3-4 曾推翻本批次自己先写的两条断言；S4-1 推翻了卡片点名的「铁金库债务」设计。**发现卡片原文与代码不符时，改卡片并在执行记录里写明理由，不要硬凑完成任务指标**。
9. **概率类断言必须用真实 Dart 跑一遍**：`dart run xxx.dart` 单文件脚本**在本机可用**（不依赖 Flutter SDK）。注意 `rng(seed)` 是**按回合确定性播种**的，故这类测试是**可复现测试**而非概率测试——可以也必须算准。
   ⚠️ **更硬的版本（S4-6 翻车两次换来的）**：**不要把「跑 N 回合应该能等到」当断言**，除非算得出 N 的命中率，且算的时候必须把**运行期状态漂移**算进去——门槛会随属性漂移失效，**时钟还会被 `endGame()` 冻结**（`Player.defaultPlayer()` 的 `hunger` 走构造器默认值 **0**，约第 17 回合就饿死，此后 `advanceMonth` 全是空转）。S4-6 初版赌「60 回合」翻过一次，修完赌「300 回合余量充足」**又翻一次**（零命中概率 3.5%，CI 恰好踩中）。**算不出确定值就注入受控依赖**（`GameEngine(events: ...)` 注入单事件池 ⇒ 概率成分归零）。
