## 九、事件触发规则

>📌 **S4-3（P1-10）口径更正**：本节原有一张「事件触发概率」分类型表（政治 10% / 家族 15% / 日常 50% …），
> 经取证**与代码无任何对应关系**——`balance_data` 里根本不存在 `eventTypeWeights`，
> 引擎也没有任何按类型加权的抽取逻辑。该表是**设计意图的臆写，从未生效**，现已删除并替换为
> 下表的真实机制描述。**历史原文按项目纪律保留在下方「历史快照」段，不回改。**

### 事件触发条件

事件的 `triggerConditions` 为**键值对**（不是自然语言），全部判定收口于
`lib/core/event_trigger_eval.dart` 的 `eventTriggersSatisfied`（Batch 10-104 单一真相）。

支持的键：

| 类别 | 键 |
|---|---|
| 时间 | `season`（另接受通配值 `any`） |
| 地点 / 家族 / 身份 | `locationId`、`familyId`、`identity` |
| 数值下限 | `minAge`、`maxAge`、`minGold`、`minReputation`、`minHealth`、`minEnergy`、`minHunger` |
| 数值上限 | `maxHealth`、`maxEnergy`、`maxHunger` |
| 前缀键 | `hasItem.<物品id>`、`skills.<技能名>`、`attributes.<属性名>` |
| 标记 | `flag`、`noFlag`、`isAlive` |

> ⚠️ **别与效果键混淆**：`army` / `diplomacy` / `military` / `magic` 这四个名字在
> **效果通道**（`choice.effects`）里确实存在（当前 19 处），但那是 P1-03 的**幽灵效果键**
> （引擎不落盘），与本节的**门槛通道**无关。
> 作为 `triggerConditions` 门槛键时它们**实测 0 处**：S3-1 已把挂在选项上的
> 26 处此类**死门槛**从数据中删除，设计意图改由 S4-3c 立项承接。

- **空 `triggerConditions` = 无门槛**：任何时候都可能浮现。当前 **41/71** 个事件属此类。
- **未知键一律放行**（不拒收），为的是旧存档里已序列化的自定义门槛不会在升级后突然失效。
  换言之：门槛键写得引擎不认，等于没写——这正是 S4-3 修复前「41 个无门槛」以外那些
  「有门槛也不生效」事件的根因。

### 事件触发概率（真实机制）

**代码里不存在任何按事件类型的权重表。** 实际机制是两级：

**第一级 · 是否浮现**（`mixin_play.dart` `_maybeWorldEvent`，月度钩子）
- 每月 **30%** 概率浮现一条传闻（`rnd.nextDouble() >= 0.3` 即返回空）；
- 门槛不满足的事件在这一级已被 `getAvailableEvents` 剔除；
- 池内用 `rnd.nextInt` **均匀随机**取一条——即**类型分布完全由池子成分决定**，
  没有任何按类型的加权。

**第二级 · 注入 AI prompt**（`services/event_prompt_filter.dart` `selectEventsForPrompt`）
- **先按门槛过滤**（S4-3 修复，此前只排序不筛选）；
- 再按相关度打分排序：地点命中 +3、季节命中 +2、数值/标记每项 +1；
- 最后截取前 `kAiPromptEventBudget` = **12** 条注入 prompt。

因此「某类型事件的出现频率」= 30% × 该类型在可用池中的占比。实测可用池构成如下
（无门槛事件恒进入，故各季节/地点组合均有 50+ 条可用，远超预算 12）：

| 类型 | 事件数 | 占 71 条的比例 |
|---|---|---|
| economic | 13 | 18.3% |
| political | 11 | 15.5% |
| family | 11 | 15.5% |
| war | 8 | 11.3% |
| religious | 6 | 8.5% |
| magical | 6 | 8.5% |
| daily | 6 | 8.5% |
| adventure | 5 | 7.0% |
| supernatural | 5 | 7.0% |

>这张表是**当前池子的构成快照**（等价于均匀随机下的期望分布），
> 不是刻意设计的权重。若日后要让某类事件更/更少出现，
> 需在 `balance_data` 新增 `eventTypeWeights` 并改造抽取逻辑（**尚未立项**）。

### 事件触发限制

- 每月最多浮现一次传闻（30% 概率判定，单次）；
- prompt 注入受 `kAiPromptEventBudget` = 12 条预算约束；
- 门槛不满足的事件在浮现与注入两级都会被剔除（S4-3 起）。

## 十、事件影响规则

> ⚠️ **本节整体是「未实现的设计稿」，不是引擎契约**（S5-2 取证，2026-10-07）。
>
> 本节声称存在「政治 / 宗教 / 魔法 / 战争」等影响维度与「轻微 / 中等 / 重大 / 灾难」
> 四档影响程度。**引擎里没有任何对应的字段、阈值或判定逻辑**——
> `Player` 只有 gold / reputation / health / energy / hunger / age /
> skills(13键) / attributes(6键) / relations / flags / inventory，
> 且**世界观层面的「政治」「宗教」并不是玩家身上可加减的量**。
>
> 📌 **这段设计稿唯一的实际产物是一批写错键名的数据**：
> 事件数据里曾有 74 处 `political` / `faith` / `military` / `magic` /
> `familyRelation` / `food` / `happiness` / `knowledge` / `north` / `allyRelation`
> 顶层效果键，即照着上面这份清单命名、但引擎从未实现。
> **S5-2 已把这 74 处全部删除**（零行为变化：它们本就一律被拒收、从未落盘）。
> S4-5 把事件选项接入主流程后，这 74 处曾让 **74/223 = 33% 的事件选项**
> 在结算时显示「（其中 1 项效果未生效：political）」，删除后该提示归零。
>
> **新增事件时请只用 `applyEffects` 支持的键**（`docs/07_AI提示词.md` §四
> 是唯一权威口径）。若日后要真正实现「政治资本 / 信仰虔诚度」这类子系统，
> 必须同时补齐取值域与钳制、玩家可见展示、以及**真实的消费端**，
> 否则只会重新制造幽灵键。详见 `docs/03-审查接力.md` 第 5 节 S5-2 卡片。
