### M1-T01 · metadata 增加 schemaVersion

- **优先级**：P0
- **涉及文件**：`lib/services/save_service.dart`（改）
- **现状**：存档 metadata 仅 `{saveId, playerName, saveTime, year, month, turnCount}`，无版本概念；写入时在 `saveGame` 内拼 Map。
- **目标**：所有新写入的存档 metadata 带 `schemaVersion: 1`；版本号定义为顶层常量 `const int kSaveSchemaVersion = 1;`，集中放在 save_service.dart 顶部。
- **实施步骤**：
  1. 在 save_service.dart 顶部定义 `const int kSaveSchemaVersion = 1;`
  2. 找到拼 metadata Map 的位置，加 `'schemaVersion': kSaveSchemaVersion`
  3. 不改读档逻辑（本任务只管写入）
- **验收标准**：
  - `flutter test` 全绿（既有测试不受影响）
  - 手动跑一次保存，检查产出 JSON 文件含 `"schemaVersion": 1`
- **禁止改动**：`lib/models/*`、`lib/providers/*`、任何 mixin
- **接口约定**：`kSaveSchemaVersion` 为 public 顶层常量，后续 T03/T04 引用。

### M1-T02 · 模型 fromJson 防御式改造

- **优先级**：P0
- **涉及文件**：`lib/models/player.dart`、`lib/models/marital.dart`、`lib/models/npc_task.dart`、`lib/models/event.dart`（改）；其余模型（family/location/npc/system）为静态数据不入存档，不动
- **现状**：fromJson 使用 `json['x'] as String`、`json['y'] as int` 等强转，缺字段或类型不符即抛异常。
- **目标**：所有 fromJson 字段读取改为安全转换：缺失/类型错时用默认值兜底，绝不抛出。允许新增文件级私有辅助函数（如 `_str(Map, key, [fallback])`、`_int(...)`、`_list(...)`），每个模型文件内自带给各字段的合理默认值（数值 0、字符串 ''、列表 []、可空字段 null）。
- **实施步骤**：
  1. player.dart 先改（字段最多，含婚姻/任务/谱系嵌套对象；嵌套对象本身缺失时整体给 null 或默认实例）
  2. marital.dart / npc_task.dart / event.dart 同样处理
  3. 列表字段（如 history 内嵌结构）逐元素 try-parse，坏元素跳过不抛
- **验收标准**：
  - `flutter test` 全绿
  - 新增测试断言：`Player.fromJson({})` 不抛异常且返回可用默认实例；`Player.fromJson({'gold': 'abc'})`（错误类型）不抛且 gold 为默认值
- **禁止改动**：toJson 逻辑一字不动（写入格式不变）；模型字段定义不增删
- **接口约定**：fromJson 签名不变（`factory X.fromJson(Map<String, dynamic> json)`），仅内部实现变宽容。

### M1-T03 · 迁移机制 save_migration.dart

- **优先级**：P0
- **涉及文件**：`lib/services/save_migration.dart`（新建）、`lib/services/save_service.dart`（改）
- **现状**：读档直接把 JSON Map 交给 fromJson，无版本感知。
- **目标**：新建迁移器：`Map<String, dynamic> migrateSave(Map<String, dynamic> raw)`——读取 `raw['metadata']['schemaVersion']`（缺失视为 0），按迁移函数表从旧版本逐级升到 kSaveSchemaVersion。v0→v1 迁移为空操作（仅补 schemaVersion 字段），因为 v1 的差异由 T02 的防御式 fromJson 吸收。save_service 读档时先过 migrateSave 再解析。
- **实施步骤**：
  1. 新建 save_migration.dart：`typedef MigrationFn = Map<String,dynamic> Function(Map<String,dynamic>)`，内部 `_migrations = <int, MigrationFn>{0: _v0ToV1}`
  2. `_v0ToV1` 只补 `'schemaVersion': 1`，state 不动
  3. `migrateSave` 循环应用直到版本 == kSaveSchemaVersion；版本**高于** kSaveSchemaVersion 时抛 `UnsupportedSaveVersionException`（自定义异常类，同文件定义）
  4. save_service 读档入口调用 migrateSave
- **验收标准**：
  - 无 schemaVersion 的旧格式 JSON（手工构造）可正常加载
  - schemaVersion=999 的 JSON 加载抛 UnsupportedSaveVersionException（测试断言）
  - `flutter test` 全绿
- **禁止改动**：toJson；`lib/models/*`（T02 已改完，本任务不碰）
- **接口约定**：`migrateSave(Map) -> Map`（纯函数，不碰文件IO）；异常类型 `UnsupportedSaveVersionException implements Exception`，带 found/expected 字段。

### M1-T04 · 读档健壮性：try/catch + 坏档隔离

- **优先级**：P0
- **涉及文件**：`lib/services/save_service.dart`（改）
- **现状**：读档/列表流程遇损坏 JSON 行为未防护，可能抛穿 UI。
- **目标**：所有文件读取与 jsonDecode 包 try/catch；单个存档解析失败时：该文件重命名为 `xxx.json.corrupted`（已存在则覆盖），从可用列表中剔除，不影响其他存档；`loadGame` 对指定坏档返回明确的失败结果而非抛穿（返回 null 或 Result 类型，按现有代码风格选）。
- **实施步骤**：
  1. `listSaves`：逐个文件 try { 读+decode+取 metadata } catch { 改名 .corrupted，跳过 }
  2. `loadGame`：try { 读+decode+migrateSave+fromJson } on UnsupportedSaveVersionException { 向上抛（UI 要专门提示） } catch { 改名 .corrupted，返回 null }
  3. 导入存档（import）入口同样过 try/catch + migrateSave 校验
- **验收标准**：
  - 目录中放入一份乱码 save_bad.json：listSaves 不抛且返回其余正常存档；文件被改名 save_bad.json.corrupted
  - loadGame 坏档返回 null；高版本档抛 UnsupportedSaveVersionException
  - `flutter test` 全绿 + 新增用例覆盖以上三条
- **禁止改动**：settings_screen.dart（UI 提示在 T05）；`lib/models/*`
- **接口约定**：listSaves 返回类型不变；loadGame 失败语义：坏档→null，高版本→异常。
