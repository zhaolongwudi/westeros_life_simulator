## 四条最容易踩的坑（详细版见 `docs/03` 第 4 节与第 5 节执行记录）

1. **取证纪律**：每次断言先 grep/find 核实再写，不要凭印象写代码事实。这条纪律已多次推翻本项目**自己**写下的断言（S3-4 两条、S4-1 的铁金库、S4-2 的长冬、S5-1 的「9 个死选项」、S4-3 的 P2-03 定性）。**发现卡片原文或既有文档与代码不符时，改卡片并写明理由，不要硬凑完成任务指标。**
2. **本地验证盲区**：本机 Flutter 是 Dart 2.17 < 项目要求的 3.12.0，**跑不了 `flutter analyze` / `flutter test`**。`check_*` 脚本与括号检查全绿**不代表测试断言没过期**——在这个项目里 **`grep test/` 就是本地等价替代**。S4-2 曾因此首推 CI 挂 7 例。
3. **改数据 / 枚举 / 文案前，先 `grep -rn <值> test/`**：本项目测试大量断言文案与枚举值，改数据必然波及。**修复不是删测试，而是把断言改成锁定「变更后应保留的契约」**（S4-3 就遇到一处**锁住 bug 的测试**）。
4. **概率类断言必须用真实 Dart 跑一遍**：`dart run xxx.dart` 单文件脚本**在本机可用**（不依赖 Flutter SDK）。注意 `rng(seed)` 是**按回合确定性播种**的，故这类测试是**可复现测试**而非概率测试——可以也必须算准。
   ⚠️ **更硬的版本（S4-6 翻车两次换来的）**：**不要把「跑 N 回合应该能等到」当断言**，除非算得出 N 的命中率，且算的时候必须把**运行期状态漂移**算进去——门槛会随属性漂移失效，**时钟还会被 `endGame()` 冻结**（`Player.defaultPlayer()` 的 `hunger` 走构造器默认值 **0**，约第 17 回合就饿死，此后 `advanceMonth` 全是空转）。S4-6 初版赌「60 回合」翻过一次，修完赌「300 回合余量充足」**又翻一次**（零命中概率 3.5%，CI 恰好踩中）。**算不出确定值就注入受控依赖**（`GameEngine(events: ...)` 注入单事件池 ⇒ 概率成分归零）。
