# assets/data — 只读导出镜像（**S4-4 决策：正式确认此定位**）

本目录下的 7 份 JSON **不是运行时数据源**，而是 `lib/data/*.dart` 的**单向导出镜像**。

- 生成方式：`python3 scripts/dart_content_extract.py`
- 校验方式：`python3 scripts/check_content_sync.py`（+ `check_docs_sync.py`、`batch10_121`、`m4c1`）
- `pubspec.yaml` **刻意不声明 `assets:`**，这 7 份文件不会被打进 APK，**运行时从不加载它们**。

因此：

1. **改这里的 JSON 不会改变任何游戏行为**。要改内容，请改 `lib/data/*.dart`。
2. 改动 `lib/data/*.dart` 后**必须**重跑导出脚本再提交，否则对账脚本（CI 会跑）会失败。

---

## S4-4 决策（2026-10-07）：确认镜像定位，**不做** JSON 外置

`docs/02-roadmap.md` 的 M4 原定完成态是「只改 `assets/data/events.json` 加新事件，
不改一行 Dart，热重启即可触发」。**该目标已被正式放弃**，理由如下（均为实测取证）：

1. **「改 JSON 免改代码」对本项目不成立。** 本作是**离线单机 APK**：全库无内容下载
   通道（`dio` 只用于 AI 叙事 API），无应用内内容编辑器，JSON 即便打进 APK 也随包发布。
   「改 JSON」与「改 Dart」**同样都要重新构建并安装 APK**，外置带来的迭代收益是零，
   而 M4 承诺的「热重启即可触发」在离线包里**无法兑现**。
2. **外置会丢掉编译期安全，而本项目正反复栽在这上面。** 外置后键名拼错、
   枚举值写错、引用悬空都只能在运行时暴露——P1-03 的 10 种幽灵效果键、
   S3-1 发现的 5 个「镜像不可反序列化」bug，全部是这类问题的实例。Dart 常量
   能在编译期拦下它们，这是本项目最便宜的一道闸门。
3. **外置的迁移面很大，收益却不成比例。** 7 个域中 `Item` 与 `NpcTaskTemplate`
   **没有 `fromJson`**；数据常量是 `const`，改成运行时加载需要异步初始化，
   而 `allEvents` / `allNpcs` 等被 **122 个测试文件**直接引用（`allEvents` 19 个、
   `allNpcTaskTemplates` 11 个……），改造面覆盖整个测试基线。
4. **镜像今天已经在产生真实价值**，不是死资产：它是对账与反序列化往返的**交叉验证
   工件**（S3-1 靠它抓出 5 个真 bug、修了 1 处悬空治主引用），并由三道 CI 闸门守着。
   保留它、并把定位说清楚，比推翻架构更划算。

**什么情况下应该重新考虑外置**：若将来真的引入**内容更新通道**（应用内下载 / 云端
内容包 / 可视化编辑器），那么「改内容不改代码」的收益才真正成立，届时再立项外置
（前置条件已记录在 `docs/specs/content-schema.md` §8/§10）。

**本决策由测试锁定**：`test/batch12_s44_json_mirror_position_test.dart` 断言
① `pubspec.yaml` 不得声明 `assets:`；② `lib/` 下不得出现 `rootBundle` 等运行时资产加载；
③ 本文件必须存在并写明「不是运行时数据源」。**要改这个决策，必须同时改那个测试**——
以此防止「加了 `assets:` 却仍用 Dart 常量」这种半迁移状态悄悄出现。

详见 `docs/03-审查接力.md` 的 P1-01 / S4-4。
